# ULTARI

사진 파일에 남은 촬영 흔적을 **브라우저 안에서** 측정하고, 그 측정값을 근거로 등급을 발급합니다.

> AI를 안 썼다는 걸 증명하는 게 아닙니다. 사람이 만들었다는 흔적을 남기는 겁니다.

하지 않는 주장: AI 이미지 탐지, AI 학습 차단, 100% 정확도.

---

## 타협 불가 원칙

**업로드된 이미지는 서버로 전송되지 않습니다.** 업로드 엔드포인트가 없고, 서버가 없고,
데이터베이스가 없습니다. 소스 전체에 `fetch`, `XMLHttpRequest`, `WebSocket`, `form action`이
하나도 없습니다. 확인하려면 개발자 도구의 네트워크 탭을 켜고 검증해 보십시오.
외부로 나가는 요청은 Pretendard 글꼴(jsDelivr) 하나뿐이고, 이 사실은 `/privacy`에 적어 두었습니다.

## 실행

```bash
npm install
npm run dev        # http://localhost:5173
npm run build      # dist/
npm run preview
```

`vite.config.js`의 `cleanUrls` 플러그인이 개발/프리뷰 서버에서 `/how` → `how.html`을 처리합니다.
Cloudflare Pages는 같은 규칙을 기본으로 제공합니다.

| 항목 | 값 |
|---|---|
| 빌드 명령 | `npm run build` |
| 출력 디렉터리 | `dist` |

정적 파일만 올라갑니다. 함수도 바인딩도 필요하지 않습니다.

## 배포 전에 반드시 고쳐야 하는 것

`src/queue.js` 한 파일입니다.

```js
export const CONTACT = 'hello@ultari.kr';   // ← 실제로 받을 수 있는 주소로
export const REVIEW_QUEUE = { updatedAt: '2026-09-11', grade2: 0, grade1: 0, archive: 0 };
```

- `CONTACT`는 자리표시자입니다. 실제 주소로 바꾸십시오. 심사 접수, 아카이브 접수, 피드백이
  모두 이 주소 하나를 씁니다.
- `REVIEW_QUEUE`의 숫자는 **실제 접수 건수**입니다. 서버가 없으므로 접수함을 확인하고 손으로
  갱신합니다. 0건이면 0건이라고 씁니다. 진위를 파는 서비스가 대기열을 부풀리면 그 순간
  팔 물건이 없어집니다.

```

articles/index.html  articles/*.html
src/

    pixels.js        측정용 픽셀 준비 (원본 배율 타일 + 축소본)
    exif.js          촬영 메타데이터. GPS는 존재 여부만.
    consistency.js   EXIF 주장 대 픽셀 물리 — 이 서비스의 핵심
    optics.js        비네팅 / 색수차 / 초점 연속성
    compression.js   8×8 블록 격자, 재압축, 영역별 편차

  grade.js           측정 결과 → 세 가지 판정
  watermark.js       마크 합성 (위치 선택, 원본 해상도 출력, 마크만 투명 PNG)
  queue.js           심사 대기 건수와 접수처
  site.js            모든 페이지 공통 (아이콘, 대기 건수, 메일 링크)
  ui.js              검증 도구 화면
  style.css          디자인 시스템
public/favicon.svg   울타리 마크
```

### 두 개의 투입구

첫 화면에 파일을 넣는 곳이 둘입니다.

| | 간단 검사 | 상세 검사 |
|---|---|---|
| 걸리는 시간 | 30초 | 며칠~몇 주 |
| 누가 | 기계 | 기계 + 사람 |
| 최대 | 3등급 | 1등급 |
| 결과 | 즉시 판정 + 인증 마크 | 같은 측정 + 사람 심사 신청서 |

둘 다 브라우저 안에서 같은 측정을 합니다. 상세 검사는 그 결과를 사람이 읽을 신청서로
만들어 주고, 접수는 메일로 받습니다. 이 사이트는 어느 쪽에서도 파일을 전송받지 않습니다.

### 진행 상황을 보여 주는 일

검사가 돌아가는 동안 7단계 목록이 완료/진행 중으로 표시되고, 끝나면
`검사 완료 · 7단계 · 0.8초`가 그대로 남습니다. 진행이 안 보이면 사용자는 업로드가 안 된
줄 압니다. 같은 자리에 "이 기기에서 계산 중입니다. 업로드가 아닙니다"를 붙여 두었고,
끝나면 과거형으로 바뀝니다.

### 인증 마크

3등급을 받으면 **버튼을 누르지 않아도** 마크가 새겨진 미리보기가 결과 화면에 바로 뜹니다.
마크에는 울타리 도형, 등급, 원본 지문 앞자리가 들어갑니다.

- **위치 선택** — 좌측 하단(기본) / 우측 하단 / 좌측 상단 / 우측 상단. 바꾸면 미리보기가
  즉시 다시 그려집니다.
- **마크 넣은 사진 내려받기** — 미리보기는 긴 변 1100으로 줄여 그리고, 내려받기는 그때
  원본 해상도로 다시 그립니다. 축소본을 원본인 척 내주지 않습니다.
- **마크만 내려받기** — 명판만 담은 투명 PNG. 크기는 그 사진에 얹었을 때와 같으므로
  편집 프로그램에서 1:1로 올리시면 됩니다.

합성은 Canvas로 브라우저 안에서 하고, 명판 높이는 짧은 변의 5~6%로 잡았습니다.
마크를 넣으면 파일의 바이트가 달라져 지문도 달라지므로 마크 안에 원본 지문을 같이 새기고,
그 사실을 화면에도 적습니다.

### 파일 선택이 되지 않던 문제

처음 구현은 드롭존에 클릭 핸들러를 걸고 그 안에서 `input.click()`을 불렀습니다. 이렇게 하면
프로그램이 만든 클릭이 다시 드롭존으로 버블링돼 클릭 한 번에 이벤트가 두 번 도달하고,
브라우저에 따라(특히 iOS Safari) 파일 선택창이 아예 열리지 않습니다.

지금은 숨긴 `<input>`을 `<label for>` **바로 앞**에 두고 브라우저의 기본 동작에 맡깁니다.
JS는 `change`와 드래그 앤 드롭만 듣습니다. 헤드리스 Chromium에서 클릭당 선택창이 정확히
1회 열리는 것과 키보드로도 열리는 것을 확인했습니다.

`src/verify/pixels.js`와 `src/queue.js`는 명세의 파일 목록에 없지만 추가했습니다.
전자는 여섯 모듈이 같은 디코딩 결과를 나눠 쓰기 위한 것이고(원본 2400만 화소를 통째로
ImageData로 올리면 96MB가 필요합니다), 후자는 대기 건수와 접수처가 두 페이지에서 쓰여
단일 출처가 필요하기 때문입니다.

### 왜 해상도를 둘로 나누는가

노이즈, JPEG 8×8 격자, 색수차, 모아레는 **원본 배율에서만** 살아남습니다. 축소하면 인접 화소가
평균되면서 재려던 신호가 사라집니다. 반면 비네팅과 초점 분포는 화면 전체의 저주파 특성이라
축소본이 더 안정적입니다. 그래서 `pixels.js`가 3×3 위치의 원본 배율 타일(512×512, 8의 배수
정렬)과 긴 변 1280의 축소본을 함께 만듭니다.

## 판정 규칙

결과는 셋뿐입니다. **“AI입니다”나 “AI 의심”은 어떤 경우에도 출력하지 않습니다.**

| 결과 | 조건 |
|---|---|
| 3등급 발급 | 촬영 정보가 있고, 정합성 모순이 없음 |
| 판정 불가 | EXIF 없음 / 촬영 기기 없음 / 촬영 시각 없음 / 화소 부족 |
| 보류 | 정합성 모순 1건 이상, 또는 약한 신호 2건 이상 |

- **정합성 모순** (`consistency.js`): ISO 대 실측 노이즈 불일치, 노이즈-신호 역전, 노이즈-신호 균일
- **약한 신호**: 렌즈 흔적 없음, 초점 불연속, 압축 격자 영역별 편차

약한 신호는 혼자서는 판정을 바꾸지 않습니다. 하늘과 나뭇잎만으로도 값이 크게 벌어지고,
카메라 내 보정과 크롭이 렌즈 흔적을 지우기 때문입니다. 오탐으로 창작자를 모욕하는 대가가
미탐보다 큽니다. 이 조합 규칙은 `src/grade.js`의 `T.softSignalsForHold` 한 줄입니다.

화면 재촬영 신호(모아레, 평면성)는 **등급을 깎지 않습니다.** 기계가 확정할 수 없는 자리라
표시만 하고 2등급 심사로 넘깁니다.

### 합격선

각 모듈 상단의 `const T = { ... }`에 모여 있습니다. **화면에 노출하지 않습니다.** 측정값과
판정 단어는 전부 공개하되, 합격선을 공개하면 그 선에 딱 맞춘 파일을 만드는 일이 쉬워집니다.

## 검증 방법

브라우저가 없는 환경에서도 측정 로직을 확인할 수 있도록, 합성 이미지로 각 모듈을 돌려
값을 대조했습니다. 확인한 것:

- 포아송 노이즈를 넣은 화면에서 휘도 8구간의 σ가 단조 증가하고 상관이 +1.00
- 노이즈를 평탄하게 만들면 상대 폭 0.02로 떨어지고 균일 플래그가 섬
- 비네팅 0.3을 넣으면 코너/중앙 0.77, 넣지 않으면 0.97
- 색수차를 넣으면 0.5~0.8px, 넣지 않으면 0.00px
- 8×8 블록 DC 오차를 넣으면 격자 세기 1.31, 3픽셀 어긋난 두 번째 격자를 얹으면 2차 피크 1.32
- 왼쪽 1/3에만 격자를 빼면 격자 약한 구역 3개가 잡힘
- 모아레를 주입했을 때만 주파수 피크가 검출됨

실제 브라우저(Chromium)에서 Canvas로 JPEG을 인코딩하고 EXIF를 붙인 파일로
세 가지 판정 경로를 모두 확인했고, 검증 중 발생한 네트워크 요청에 GET 이외는 없었습니다.

## AdSense

- 광고 자리는 `.ad-slot`으로 레이아웃에만 잡혀 있습니다. **스크립트는 넣지 않았습니다.**
  승인 전에 넣으면 의미가 없습니다.
- `/privacy`와 `/terms`가 있고, 개인정보 처리방침에 이미지가 전송되지 않는다는 사실을
  명시했습니다.
- `/articles/`에 글 3편이 있고, `/archive`와 `/roadmap`도 읽을 내용이 있는 페이지입니다.
  도구 하나만 있는 사이트는 “가치가 낮은 콘텐츠”로 거절될 가능성이 높습니다.
  **글이 더 쌓이기 전에는 신청하지 않는 편이 낫습니다.**
- 중복 페이지를 만들지 않았습니다. 탐색은 6개 항목 한 줄입니다.

## 알려진 한계 (구현 쪽)

- RAW와 일부 HEIC는 브라우저가 디코딩하지 못합니다. 서버가 없으므로 변환해 줄 수도 없습니다.
- 노이즈 측정은 JPEG 저장 화질에 크게 영향을 받습니다. 화질을 낮춰 저장하면 노이즈가 깎입니다.
- 압축 격자 추정은 휴리스틱입니다. 양자화 테이블을 직접 읽지 않습니다.
- 센서 지문(1등급)은 구현돼 있지 않습니다. 접수만 받습니다.
- 오리지널 아카이브는 접수만 받습니다. 판매도 배분도 이루어진 적이 없고, 그래서 배분 비율을
  숫자로 적지 않았습니다.
- 인증 마크는 사진 위에 그린 그림입니다. 지우거나 흉내 낼 수 있습니다. 마크가 아니라
  마크에 적힌 지문이 대조의 근거입니다.

검증 자체의 한계는 `/limits`에 따로 적어 두었습니다. 그쪽이 더 중요합니다.
